1. 新增**公共组件** `showLuoboAnchoredMenu`（锚定毛玻璃菜单），补齐 §2.3 里 5 种浮层范式中**唯一还没落地**的一种。

## 3. 组件设计：`showLuoboAnchoredMenu`

新文件：`lib/widgets/luobo/anchored_menu.dart`（与 `sheet_shell.dart` 平级）。

### 3.1 API

```dart
class LuoboAnchoredMenuItem<T> {
  const LuoboAnchoredMenuItem({
    required this.value,
    required this.label,
    this.trailing,      // 排序场景：方向箭头
  });
  final T value;
  final String label;
  final Widget? trailing;
}

/// 锚定毛玻璃菜单 —— 贴在 [anchorKey] 所指元素旁边浮出。
///
/// 返回用户点中的值；点遮罩/返回键取消时返回 null。
Future<T?> showLuoboAnchoredMenu<T>({
  required BuildContext context,
  required GlobalKey anchorKey,
  required List<LuoboAnchoredMenuItem<T>> items,
  T? selected,
  double width = 200,
});
```

- **锚点用 `GlobalKey`**（而不是传 `Offset`）：调用方把 key 挂在触发元素上，组件内部 `localToGlobal` 算矩形，避免调用方自己做坐标换算。
- 面板**固定宽 200dp**（对齐实测）；项文字超长省略。
- **无居中标题**（与 Sheet 的区别之一）。

### 3.2 定位与避让规则

1. 水平：默认**右对齐锚点右边缘**（飞牛贴的是右侧图标）；若左侧空间不足则改左对齐。
2. 垂直：默认在锚点**下方 8dp**；若下方空间不足 → **向上翻转**，改为在锚点上方 8dp。
3. 与屏幕四边至少留 **16dp**（`LuoboSpacing.pageX`）。
4. 面板高度超过「可用高度 − 32dp」时，内部可滚动（`maxHeight` + `SingleChildScrollView`）。
5. 锚点未挂载（页面已被 pop）→ **直接返回 null，不弹**（安全阀）。

### 3.3 视觉规格（全部走 token）

| 项 | 取值 |
|---|---|
| 材质 | `LuoboGlassSurface`（`blur 24` + tint + 描边 0.8 + 阴影）—— **小面积固定元素 ✅ 不撞性能红线**（§5） |
| 圆角 | `LuoboRadius.group`（20） |
| 项高 | 新增 `LuoboSpacing.menuItemHeight = 64` |
| 面板上下内边距 | 8dp |
| 项内左右内边距 | `LuoboSpacing.rowX`（16） |
| 选中：勾 | 左 `AppIcons.check`，`LuoboAccent.accent`，16 |
| 选中：方向箭头 | 右 `AppIcons.down` / `up`，`LuoboAccent.accent`，15 |
| 文字 | `LuoboType.body`（14） |

### 3.4 动画

| 阶段 | 参数 |
|---|---|
| 进场 | `LuoboMotion.sheet`（250ms）+ `LuoboMotion.enter`（`easeOutCubic`） |
| 进场效果 | **淡入 + 缩放**：`scale 0.92 → 1.0`，`alignment` **指向锚点**（面板从锚点方向"长出来"） |
| 出场 | 反向、更短（150ms，`LuoboMotion.micro` + `LuoboMotion.exit`） |
| 遮罩 | `LuoboMotion.scrim`（黑 .42），点击关闭 |

> 这正是与单选 Sheet（底部滑入）**观感差异的来源**，也是用户说"动画效果也不一样"的点。

## 4. 排序模型改动

### 4.1 现状：7 个扁平枚举值

```dart
enum SongSortOption { titleAsc, titleDesc, artistAsc, artistDesc,
                      albumAsc, albumDesc, recentlyAdded }
```
`_sortSongs()` 里 7 个 case，`artistAsc` 与 `artistDesc` 只差 `a`/`b` 交换 —— **升降各写一遍**。

### 4.2 新模型：字段 + 方向

```dart
enum SongSortField { title, artist, album, recentlyAdded }
```
- 状态：`SongSortField _sortField` + `bool _sortAscending`（`recentlyAdded` 固定降序，方向箭头不显示）
- `_sortSongs()`：**每个字段一个 comparator** + 方向乘子 —— **7 份 → 4 份**，且不再是复制粘贴
- `recentlyAdded` 的 `created == null` 兜底逻辑保持不变（原样搬进它的 comparator）

### 4.3 面板交互

| 操作 | 行为 |
|---|---|
| 点**未选中**字段行 | 切换到该字段，**保持当前方向** |
| 点**已选中**行的**方向箭头** | 翻转升/降（箭头热区放大到 44dp，避免点不中） |
| 点遮罩 / 返回 | 取消，不改排序 |

> ⚠️ **待确认**：飞牛是否也支持"点箭头翻转"（截图只能看出箭头存在）。若确认不是，退化为「点已选中行 = 翻转方向」。

### 4.4 l10n 影响

现有键把方向**写进了文案**：`sortTitleAz`「标题（A-Z）」/ `sortTitleZa`「标题（Z-A）」/ `sortArtistAz` / `sortArtistZa` / `sortAlbumAz` / `sortAlbumZa`；另有 `recentlyAdded`「最近添加」、`sortBy`「排序方式」。

新模型需要的是**纯字段名**：标题 / 艺术家 / 专辑 / 最近添加 —— **待核实是否已有可复用的标签键**（`app_zh.arb` 里搜到 `nameLabel`「名称」、`sortByName`「名称」，但没有裸的「标题/艺术家/专辑」标签键）。若需新增，按既有流程只改 `app_en.arb` + `app_zh.arb` 后 `flutter gen-l10n`。

> 旧键 `sortTitleAz` 等**先不删**（其它页面可能仍引用，需 grep 确认后再统一清理）。

## 5. 边界与安全阀

| 边界 | 处理 |
|---|---|
| **深色模式** | `LuoboGlassSurface` 深色 tint 是**黑 .50，本身几乎不可见**（§2.3 的深色玻璃陷阱）—— 面板下面**必须有内容**。列表页有 ✅。若将来用在纯色深底上，需 `strongBorder: true` |
| **性能红线** | 面板是小面积固定元素 ✅；内部**不做动画循环**（`uTime` 类驱动一律不引入） |
| **桌面端** | `all_songs_screen` 桌面端共用同一排序入口 → 会一起变成锚定面板。鼠标场景下锚定面板**比底部弹窗更自然**，判定为**可接受**；若有异议再按 `NavigationHelper.isDesktop` 分支保留旧样式 |
| **无障碍** | 面板需 `Semantics(button: true, selected: ...)`；遮罩可点关闭；Esc/返回键可关（`showGeneralDialog` 默认支持返回键） |
| **退化** | 锚点未挂载 / 屏幕空间为 0 → 不弹，返回 null |

## 6. 测试与验收

### 6.1 单测（可自动化）

- `SongSortField` 的 4 个 comparator × 升降 = **8 组**排序结果断言
- `recentlyAdded` 的 `created == null` 前后置兜底
- **回归等价性**：对同一组样本歌单，`(field, ascending)` 的排序结果必须与**旧 7 项枚举**逐一等价 —— 这条是防"重构把排序改坏"的关键

### 6.2 Widget 测试

- 面板定位：给定屏幕尺寸与锚点位置，断言面板右边缘对齐锚点、垂直在下方
- 空间不足时**向上翻转**
- 选中项渲染勾 + 方向箭头；未选中项**不渲染任何指示**

### 6.3 真机验收清单（**必做**）

1. 面板贴右侧触发图标，右边距 16dp；圆角/描边/半透明质感与飞牛一致（**不是实心白块**）
2. 动画是**从锚点淡入缩放**，不是底部滑入
3. 选中项：玫红勾 + 方向箭头；未选中项干净
4. 深色模式下可见（底下有列表内容）
5. **排序结果与改动前一致**（拿同一份曲库对比）
6. 列表滚到底部时，面板**向上翻转**且不越界

> ⚠️ **诚实边界**：毛玻璃的"质感"与动画手感**测不出来**，只能真机看。`flutter analyze` + 单测只能证明「没编译错、排序没改坏」。

| 清理 | 8 个因本次改动变成死键的旧排序 l10n 键（`sortTitleAz/Za`、`sortArtistAz/Za`、`sortAlbumAz/Za`、`sortByTitleAZ/ZA`） |

**⚠️ 实施中踩到的两个坑（记下来免得重犯）**

1. **`recentlyAdded` 的 comparator 自带方向，不能再取反**。第一版写成「统一 comparator + 方向乘子」，
   对 `recentlyAdded` 传 `ascending: false` 再取反 → 结果变成「旧的在前 + `created == null` 排最前」，
   **与旧实现相反**。正解：该字段**直接调 comparator、不取反**（`created == null` 排最后 + 新的在前）。
   → 这正是「回归等价性单测」要防的东西，测试写完立刻暴露了。
2. **按行删 arb 键会踩多行 `@` 元数据**。`app_zh.arb` 里 `"@sortByTitleAZ": {` 是**跨行对象**，
   只删首行会留下 `"description": ...` 和 `},` → **JSON 直接坏掉**。正解：删到行尾为 `{` 时，
   要**连块删到配平的 `}`**，并在写盘前 `json.loads` 校验。
