> 用户诉求：「搜索页那个彩色卡片网格挺好看，把这些 item 改成 全部歌曲／全部歌手／全部专辑／歌单／收藏／有声书，上面名称改成音乐库；下面的搜索框点击以后才进入搜索页。」
> 决策已定（2026-10-23）：「不太需要最近播放和音乐风格，暂时摘掉就按现在 6 个先做。」

## 1. 结构变更

`音乐库` tab 从**TabBar 版**（收藏 / 专辑 / 歌手 / 歌曲 / 风格 / 年份，`library_screen.dart`）改为**入口页**：

```
音乐库（大标题 24/700）
[ 🔍 搜索歌曲、专辑、歌手 ]      ← 只读入口，点击 push SearchScreen（自动聚焦）
[ 全部歌曲 ] [ 全部歌手 ]
[ 全部专辑 ] [ 音乐风格→已摘 ]
[ 歌单     ] [ 收藏     ]
[ 有声书/电台 ]
```

- 新文件 `lib/screens/library_hub_screen.dart`；旧 `LibraryScreen` **保留不删**（回退路径，符合仓库约定），仅 `main_screen._mobileScreens[1]` 换成 hub；桌面端 `_screens` 暂不动。
- 卡片沿用搜索页 `_CategoryCard` 的观感（r12、渐变、左上 icon 24、左下标题 14/700、宽高比 1.6），本次不降饱和（用户：「按现在 6 个先做」）。
- 第 6 项按服务器族动态：道理鱼 = **有声书**（`AudiobookListScreen`），其余 = **电台**（`RadioScreen`）——与现有浏览分类一致。

## 10. 专辑列表加载慢（2026-10-23 修复）

**现象**：每次进入专辑列表都要等几秒。

**根因**（`albums_screen.dart` 旧实现）：`getArtists()` 之后，对前 20 位歌手**串行**逐个 `getArtistAlbums()` —— 20 次网络往返全部完成后才第一次渲染；页面每次 push 都是新 State，没有跨次缓存。

**修复**：
1. **缓存优先**：曲库已全量同步进 SQLite，`LibraryProvider.cachedAllAlbums` 同步可读 → 首帧直接出列表，`_hasMore=false`（缓存即全量）。
2. 缓存为空时才走网络：改 `getAlbumList(type: 'alphabeticalByName', size: 100, offset)` **分页**（1 次/页），替换 20 次逐歌手请求。
3. 若服务端不支持上述接口，兜底改为**并发分批**（每批 8 位歌手）逐歌手拉取，不再是纯串行；每批完成即 `setState` 增量渲染。

## 12. 歌手列表「离顶部很远」（2026-10-23 修复）

顶部到首个歌手行原本叠了：状态栏 + 56（顶栏）+ 44（计数行）+ **28（字母分组头）** = 128dp，所以看着空了一大截。fnos 的歌手列表**没有可见的字母分组头**（只有右侧 A–Z 跳转），已删除字母头，`_letterOffsets` 改为直接指向每组第一行的偏移（跳转精度不变）。现在首个歌手行与飞牛一致 ≈ 状态栏 + 100dp。

### 12.1 真正根因（2026-10-23 续）：顶栏高度被算了两遍

上一节删字母头只解决了 28dp，用户仍反馈「共 N 位歌手那一行离顶部不对」。

**实测（widget test 量坐标）**：`Scaffold(extendBodyBehindAppBar: true)` 下，**body 内的 `MediaQuery.padding.top` 已被 Scaffold 叠加成「状态栏 + AppBar 高度」**（状态 47 → body 里读到 **103**）。歌手列表的 `listTopInset(context)` 恰好写在 `Consumer` builder 里（位于 Scaffold body 内），于是留白 = 103 + 56 = **159**，比正确值多出整整一个顶栏高度（56dp）。

**修法**：`listTopInset` 必须在 **Scaffold 之外**调用——歌手页在 `build` 顶部算好 `final topInset = listTopInset(context)` 再传进 body；`list_top_bar.dart` 的注释已标注该约束。

## 13. 歌手列表：去掉 A–Z 检索 + 修正「xx 首歌」（2026-10-23）

1. **去掉右侧 A–Z 字母检索条**（用户要求）：连同 `_ArtistScrubber`、`_letterOffsets`、拼音分组逻辑一起删除；列表变成一条纯滚动列表，排序仍在计数行右侧图标里。`lpinyin` 在该文件不再使用。
2. **「N 首歌」统计口径修正**：原来只按 `song.artistId` 计数，会缺两类数据——
   - 服务端 artists 与 tracks 的 id 体系不一致（如道理鱼兼容层）；
   - 合唱曲里非第一顺位的歌手（`artistId` 只存主艺人）。

   现在同时按四条口径统计并**取最大值**：
   - `song.artistId` 匹配；
   - 歌手名匹配（优先 `artistParticipants`，否则把 `song.artist` 按 `/ , & 、 ;` 拆开）；
   - 该歌手各专辑 `album.songCount` 累加（按 `album.artistId`）；
   - 同上（按专辑 `artist` 名字）。

   专辑数仍优先用服务端 `artist.albumCount`，缺失时按 id/名字统计。
