## 1. 背景与目标

道理鱼是一套**独立、闭源**的音乐服务系统（他人部署），对外提供**双协议**：

```
192.168.31.142:4000（内网） / daoliyu.625122961.xyz:10010（远程 HTTPS）
│
├── /rest/*.view   Subsonic 兼容层（Luobo 现用）
│     认证: 明文密码 p=（token+salt 被拒 code41）
│     能力: 浏览/搜索/播放/封面/歌单/收藏（子集）
│
└── /api/*         自研 JSON 层（JWT Bearer）
      认证: POST /api/auth/login → JWT
      能力: 歌词/随机歌/播放控制/推荐/Admin
```

目标：Luobo 以 `serverFamily='daoliyu'` 独立接入，登录后全部数据走道理鱼。由于道理鱼闭源无法改造，**所有适配均为 Luobo 客户端代码改动**。

## 4. JWT 通道 + 歌词接入（核心改动）

### 4.1 新增能力（`subsonic_service.dart`）

```dart
String? _apiJwt;              // 内存 JWT
bool _apiLoginFailed = false; // 一次失败即标记，避免每首歌重复尝试登录

/// POST {activeBaseUrl}/api/auth/login
/// body: {"username": ..., "password": ...}
/// → 200 {token, user{...}}
Future<bool> loginToApi() async {
  if (_apiJwt != null) return true;
  if (_apiLoginFailed) return false;
  try {
    final resp = await _dio.post('$activeBaseUrl/api/auth/login',
        data: {'username': _config!.username, 'password': _config!.password});
    final data = resp.data as Map<String, dynamic>;
    final token = data['token'] as String?;
    if (token == null || token.isEmpty) return false;
    _apiJwt = token;
    _apiLoginFailed = false;
    return true;
  } catch (e) {
    _apiLoginFailed = true;
    Log.w('Daoliyu', 'API login failed: $e');
    return false;
  }
}

/// 带 Bearer 的 GET：401 → 重新 login 一次 → 重试
Future<Map<String, dynamic>?> _apiGet(String path) async {
  if (!await loginToApi()) return null;
  try {
    final resp = await _dio.get('$activeBaseUrl$path',
        options: Options(headers: {'Authorization': 'Bearer $_apiJwt'}));
    return resp.data as Map<String, dynamic>;
  } on DioException catch (e) {
    if (e.response?.statusCode == 401) {
      _apiJwt = null; // 过期，重登
      if (await loginToApi()) {
        final retry = await _dio.get('$activeBaseUrl$path',
            options: Options(headers: {'Authorization': 'Bearer $_apiJwt'}));
        return retry.data as Map<String, dynamic>;
      }
    }
    return null;
  }
}
```

> `_dio` 复用现有实例（`_configureCertificateValidation` 已重建），登录/歌词请求无需独立 Dio。
> 注意：自研层请求跟随 `activeBaseUrl`（LAN↔远程切换时用对应地址）。
>
> **状态重置**（易漏）：
> - `configure()` 时重置 `_apiJwt = null; _apiLoginFailed = false;`——换服务器后旧失败标记/旧 token 不得残留
> - `_setActiveBaseUrl()`（`subsonic_service.dart:87-91`）时重置 `_apiJwt = null`——LAN↔远程切换后 token 需按新地址重新登录

### 4.3 自研歌词响应转换

`GET /api/tracks/{id}/lyrics` 返回：

```json
{
  "trackId": "trk_...",
  "candidates": [ { "id": "MR", "syncType": "SYNCED",
                    "lyrics": "[00:00.00] 作曲 : ...\n[00:08.62]Let's start...\n[00:08.62]魔法开始显现\n...",
                    "lyricsPlain": "...", "available": true, "default": true } ],
  "preference": { "offsetMs": 0 },
  "effectiveCandidate": { ...同上... },
  "fallback": false
}
```

转换函数：

```dart
/// 取 effectiveCandidate.lyrics（LRC 格式，含中英交错），返回**双键**：
///   • lyrics           —— 原始 LRC（无损），供 LyricsManager 解析时间轴（车机副标题链）
///   • structuredLyrics —— 行数组 {start(ms), value}，供三个 UI 入口逐行渲染
/// 仅当 LRC 含有效时间轴行时才产出 structuredLyrics；纯文本时只返回 lyrics。
/// 见 `docs/歌词源优先级修复技术方案.md` §4 方案 C / §5.1。
Future<Map<String, dynamic>?> _getDaoliyuLyrics(String songId) async {
  final data = await _apiGet('/api/tracks/$songId/lyrics');
  if (data == null) return null;
  final candidate = data['effectiveCandidate'] as Map<String, dynamic>? ??
      ((data['candidates'] as List?)?.isNotEmpty == true
          ? (data['candidates'] as List).first as Map<String, dynamic>
          : null);
  if (candidate == null) return null;
  final lrc = candidate['lyrics'] as String?;
  if (lrc == null || lrc.isEmpty) return null;

  final result = <String, dynamic>{'lyrics': lrc};
  // LRC → 行数组：公共纯函数（P1 会替换 LRCLIB/网易云的私有等价实现）
  final lines = lrcToStructuredLines(lrc);
  if (lines.isNotEmpty) {
    result['structuredLyrics'] = [
      {'synced': true, 'line': lines},
    ];
  }
  return result;
}
```

> 解析实现落在 `lib/services/lyrics/lrc_parser.dart` 的 `lrcToStructuredLines()`（公共纯函数），不再内联一份。

- 道理鱼 LRC 是**原文/译文交错行**（同时间戳两行），`SyncedLyrics.fromLrc` / UI 解析器均按行渲染，天然支持双语显示
- `preference.offsetMs` 歌词偏移：**本迭代不接**（设置入口暂无对应 UI），保留扩展点

### 4.4 歌词取源链（道理鱼下）


## 8. 封面注意事项（坑）

道理鱼封面有**两种取法**，语义不同：

| 方式 | URL | 缓存 | 用途 |
|---|---|---|---|
| Subsonic `getCoverArt` | `/rest/getCoverArt?id=album:alb_xxx&size=` | max-age 86400 | 现有 `getCoverArtUrl()` 已用 ✅ 列表/播放页正常 |
| 自研层 coverArt | `/api/cover?path=...` | max-age=0 | 歌词/random 等自研响应里带的是这个 |

**结论**：正常浏览走现有 Subsonic 封面（已兼容）。只有自研层数据（random 歌单）里拿到的是路径式 coverArt——本迭代**不强求**其封面显示（随机歌列表可先不显示封面或用占位图），避免引入 ticket/路径式封面的额外逻辑。若体验需要再二期处理。

## 12. 与道理鱼 Web 实测能力的差距分析（2026-10-20）

> 本节为增量分析，不改变前 11 节的接入结论。实测对象：道理鱼 Web（`app-4000-chengsitom.cn68.ugdocker.link`，v0.3.4/API 1.0.0），方法：CDP 注入 fetch/XHR 钩子 + `Network` 域抓请求/响应头 + 真实播放拖动。

### 12.1 先修订一个旧结论

原实现与代码注释（`subsonic_service.dart:791-795`、`player_provider.dart:3012-3015`）认为「道理鱼转码流不支持 HTTP Range，只能靠 `timeOffset` 重起流」。**实测后需修订为**：

| 取流状态 | 状态码 | Content-Range / Accept-Ranges | 结论 |
|---|---|---|---|
| `/api/tracks/{id}/transcode` **首次（无缓存）** | 200 | 无 / 无 | 实时管道，不可 Range 定位 |
| 同一 URL **完整产出并落缓存后** | 206 | `bytes 100000-100999/3548209` / `bytes` | 可 Range 精确定位 |
| `/api/tracks/{id}/stream` | 206 | `bytes 32768-7010011/7010012` / `bytes` | 始终可 Range |

拖动实测（播放中拖到 250s）：
- 转码（缓存已生成）：`Range: bytes=3964928-` → 206，立即 `seeked`；
- `/stream`：`Range: bytes=32768-` → 206，立即 `seeked`；
- HLS：`/api/tracks/{id}/hls` 返回 VOD m3u8，3 秒分片，由 hls.js 按分片定位。

**影响**：当前「道理鱼转码 seek 一律重起流」的策略在缓存命中时属于过度设计，代价是每次拖动重建音频源、维护 `_streamBaseOffsetMs`、重同步歌词。冷转码仍应保留 `timeOffset` 兜底。

> 尚未复测：Luobo 实际调用的 Subsonic 兼容端点 `/rest/stream?maxBitRate=128&format=mp3` 的 Range 行为（需 NAS 会话）。若其结果与 `/transcode` 一致，则可直接按缓存状态切换 seek 策略。

### 12.2 差距清单（按优先级）

| 优先级 | 能力 | Luobo 现状 | 道理鱼实测行为 | 建议 |
