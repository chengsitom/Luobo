# 流沙流体背景（FluidBackground）技术文档

> 状态：**已上线两处：首页「为你制作」4 卡封面 + 首页二级页（`SongListScreen`）hero 背景**（2026-09-23）
> 代码位置：独立 pub 包 `packages/fluid_mesh_background/`（`lib/src/fluid_background.dart` / `fluid_palette.dart` / `fluid_clock.dart`）｜ 着色器：`lib/shaders/fluid_mesh.frag`
> 接入点文档：首页「为你制作」见 `docs/首页重构技术方案.md` §5.6；二级页 hero 见同文档 §5.9

---

## 1. 一句话定位

**从封面提取颜色，铺成一片持续流动的「流沙」流体场**，用作卡片/页面的动态背景。

它解决的是「静态封面拼贴 / 单色底 → 有生命力又不抢内容」这件事，观感对标 Apple Music
全屏播放页那层背景。

### 什么时候该用

- 卡片、头图、播放页这类**需要「有东西在动」但内容是别的东西**的容器背景
- 有明确取色源（封面图）的场景
- 同一屏有多个实例、且希望**每个实例看起来是各自一套动画**

### 什么时候不该用

- **需要在其上压文字**的场合：默认不带暗化遮罩，请显式开 `showScrim: true` 并实测对比度。
  ⚠️ **但 `showScrim` 是整幅暗化，压字位置分散时不要用**——它会把「不压字」的区域一起压暗，
  而**空间对比度正是「看得出在流动」的来源**。离屏实测（400×304，二级页 hero）：整幅
  `showScrim` 让中段空间对比度降到 **0.023**，改成「只暗化顶部/底部压字块」的分区遮罩后是
  **0.068（≈3 倍）**，而白字对比度几乎不变（3.97/3.56 vs 4.09/3.68）。做法见
  `首页重构技术方案.md` §5.9
- **大面积滚动区域**（长列表整页背景）：这是本项目的性能红线，见 §10。
  **页面的固定头图（hero）不在此列**——它是单实例、不随列表滚动扩张，且随
  `SliverAppBar` 折叠而收缩（二级页的做法见 `首页重构技术方案.md` §5.9）
- **没有取色源**且不接受默认深色 mesh 的场合

## 2. 快速上手

### 最小用法

```dart
import 'package:fluid_mesh_background/fluid_mesh_background.dart';

FluidBackground(
  imageUrl: coverUrl,   // 取色源；为空则回落默认深色 mesh
  borderRadius: 12,
)
```

> **App 内取色源优先传 `imageProvider`**：传 `CachedNetworkImageProvider(url,
> cacheManager: coverCacheManager, cacheKey: coverArtCacheKeyFromUrl(url))`，
> 复用封面自身的磁盘/内存缓存，**不为取色额外下载**（`imageUrl` 走裸 `NetworkImage`，
> 会另起一份下载）。

### 同屏多个实例（推荐）

用 `FluidBackgroundScope` 包住整块，让所有实例**共用一个时钟**：

```dart
FluidBackgroundScope(
  child: GridView.builder(
    itemCount: covers.length,
    itemBuilder: (_, i) => FluidBackground(
      imageUrl: covers[i],
      borderRadius: 12,
      // 关键：每项给不同 seed，否则图案结构一样、看起来像同一个动画
      seed: FluidBackground.seedForIndex(i),
    ),
  ),
)
```

### 想直接给颜色（不取色）

```dart
FluidBackground(colors: const [c1, c2, c3, c4], borderRadius: 12)
```

### 想调快慢/扭曲/颗粒

```dart
FluidBackground(
  imageUrl: url,
  style: const FluidBackgroundStyle(speed: 0.18, warp: 4.0, grain: 0.08),
)
```

### 在流体内压文字（卡片左下角，Apple Music 那种）

`FluidBackground` **没有 `child` 槽位**，文字要在宿主侧用 `Stack` 叠上去：

```dart
Stack(
  fit: StackFit.expand,
  children: [
    FluidBackground(imageProvider: cover, borderRadius: 12, seed: seed),
    // 只压底部：透明 → 黑 0.55。上半部保持通透，流动才看得出来。
    const DecoratedBox(
      decoration: BoxDecoration(
        borderRadius: BorderRadius.all(Radius.circular(12)),
        gradient: LinearGradient(
          begin: Alignment.center,
          end: Alignment.bottomCenter,
          colors: [Color(0x00000000), Color(0x8C000000)],
        ),
      ),
    ),
    Align(
      alignment: Alignment.bottomLeft,
      child: Padding(
        padding: const EdgeInsets.all(12),
        child: Column(
          mainAxisSize: MainAxisSize.min,
          crossAxisAlignment: CrossAxisAlignment.start,
          children: [/* 白色标题 15/w600 + 白色 75% 副标题 12 */],
        ),
      ),
    ),
  ],
)
```

- ⚠️ **不要用 `showScrim: true` 来实现这个**：它是**整幅**暗化（`_ScrimOverlay`，
  `fluid_background.dart:529-543`，黑 0.42→0.70），会连不压字的区域一起压暗，
  而空间对比度正是「看得出在流动」的来源。离屏实测与二级页 hero 的同一结论见 §1
  「什么时候不该用」（整幅 0.023 → 分区 0.068）。
- 文字一律用**白色**（叠在任意取色上都可读），并保证叠字区域有遮罩覆盖。
- 卡面做成**正方形**（`AspectRatio(1)`）时观感最接近 Apple Music 的专辑卡。
- 接入点：首页「快速开始」小节（漫游 / 歌单 / 收藏）三张卡，
  见 `首页快捷入口与漫游技术方案.md` §12.3。

## 3. 公共 API

### `FluidBackground`

| 参数 | 类型 | 默认 | 说明 |
|---|---|---|---|
| `imageUrl` | `String?` | null | 取色源（封面 URL），内部走裸 `NetworkImage` |
| `imageProvider` | `ImageProvider?` | null | 显式图片源，**优先于 `imageUrl`**；App 内应传 `CachedNetworkImageProvider` 以复用封面缓存 |
| `colors` | `List<Color>?` | null | 直接给 4 色，给出时忽略上面两个来源 |
| `clock` | `FluidClock?` | null | 显式时钟；为空则优先用上层 Scope，再没有就自建 |
| `style` | `FluidBackgroundStyle` | `standard` | 观感参数 |
| `borderRadius` | `double` | 0 | 圆角（内部 `ClipRRect`） |
| `showScrim` | `bool` | false | 叠一层自上而下暗渐变（上方压白字时用） |
| `seed` | `double` | 0 | 本实例的流动图案偏移，见 §8 |
| `useShader` | `bool` | true | 是否尝试流沙着色器；失败自动回落圆斑 |

来源优先级：`colors` > `imageProvider` > `imageUrl`。

静态成员：
- `FluidBackground.seedForIndex(int index)` —— 网格场景的每项 seed（45° 步进）
- `FluidBackground.driftPeriodSeconds` = 16 —— 圆斑回落路径的周期
- `FluidBackground.alignmentFor / radiusFactorFor` —— 圆斑回落路径的几何（单测用）

### `FluidBackgroundStyle`

| 字段 | 默认 | 说明 |
|---|---|---|
| `speed` | 0.27 | **流速倍率**：`着色器时间 = 真实秒数 × speed`。越小越慢 |
| `warp` | 3.2 | 扭曲强度。越大色带越平缓；太小会变成密集锯齿条带 |
| `grain` | 0.05 | 颗粒强度。调大更「沙」 |

`FluidBackgroundStyle.standard` 即上表默认值（首页当前采用的一套）。

### `FluidBackgroundScope`

`FluidBackgroundScope({required Widget child})`

让子树内所有 `FluidBackground` 共用一个 `FluidClock`，并**按 `TickerMode` 自动起停**。
自身持有 `TickerProvider`，调用方不需要是 StatefulWidget。

> **为什么必须有它**：`IndexedStack` 用 `Visibility(maintainAnimation: true)` 包未选中项，
> **TickerMode 不会被自动关掉**。不做处理的话，切到别的 Tab 后首页仍在逐帧产帧（耗电）。
> 另外每实例各起一个 Ticker 也是纯浪费。

### `FluidClock`

`FluidClock(TickerProvider vsync)` —— `ValueNotifier<double>`，值 = **单调递增的秒数**。

| 方法 | 说明 |
|---|---|
| `start()` | 启动（已在跑则无操作） |
| `stop()` | 停止，**记住当前秒数** |
| `isRunning` | 是否在跑 |

**核心语义：`stop()` 后再 `start()` 从原处续上，不是从 0 重来。** 见 §7-①。

### `FluidPalette`

`packages/fluid_mesh_background/lib/src/fluid_palette.dart` —— 封面取色，`FluidBackground`
内部用它把封面变成 4 个颜色。**外部需要「和流体同一份颜色」时也用它**（例如页面折叠态
导航栏底色，见 `首页重构技术方案.md` §5.9）。

- `FluidPalette.instance` —— 共享实例（缓存就在实例上，别自己 new）
- `colorsFor(ImageProvider?, {String? cacheKey})` → `Future<List<Color>>`（无封面/失败 → `defaultColors`）
- `cached(String? key)` → 同步读缓存（首帧直接上色，避免闪一下默认色）
- `FluidPalette.keyFor(provider, {cacheKey})` → 生成稳定缓存键
- `FluidPalette.defaultColors` —— 默认深色 mesh（Apple Music 暗色观感）
- 取色顺序（vibrant → darkVibrant → muted → darkMuted → lightVibrant → lightMuted）
  即 `colors[0]` 恒为 vibrant、`colors[3]` 偏暗；LRU 上限 24
- 取色在 `Size(112, 112)` 上做，**与播放页取色同基准**，所以同一封面在首页/二级页/
  播放页得到同一组颜色

## 4. 两条渲染路径与回落链

```
useShader && 着色器加载成功？
├─ 是 → 流沙流体场（shaders/fluid_mesh.frag）   ← 默认，也是「流沙」观感的来源
└─ 否 → 取色圆斑（1 底色 + 3 个径向渐变圆斑，与播放页 _DynamicBackground 同基准位）

颜色来源：imageUrl / colors
├─ 有 imageUrl / imageProvider → FluidPalette 取 4 色（异步，命中缓存则同步上色）
└─ 无 / 取色失败 → FluidPalette.defaultColors（默认深色配色）
```

回落是**静默**的，但会记一条诊断事件（见 §9-②）。着色器加载完成前（asset 读取的几毫秒）
先用圆斑占位，避免整块空白。

## 5. 着色器原理

`shaders/fluid_mesh.frag`（约 70 行 GLSL）。

### 为什么必须是着色器

「几个圆在动」和「流沙」是**两个物种**：

- **圆斑是离散物体** —— 有固定形状、有明确边界，眼睛必然把它读成「3 个圆」。
  给它加纹理（例如把封面模糊后贴上去）只是给圆**填了内容**，形状和运动逻辑没变。
- **流沙是连续场** —— 整幅画面被一个噪声场平流（`颜色 = f(uv + noise(uv, t))`），
  **没有东西可数**，眼睛只能看到「在流」。

所以必须**逐像素算**，即片段着色器。

### 四步

1. **噪声驱动的缓慢自转** —— 让色带方向本身也在变，避免「固定斜条带」的机械感
2. **正弦扭曲** —— 相位连续推进 → 色带持续「翻涌」，而不是来回摆动
3. **第二层噪声打散色带边界** —— **这一步是「沙」的关键**，少了它就只是几条光滑正弦带
4. **静态颗粒**（`hash21`）—— 沙粒质感。刻意做成静态：动态颗粒会闪，且大时间值下
   hash 精度会退化

### 成本

约 **9 次 hash/像素**（2 次值噪声 + 1 次颗粒），比 `mesh_gradient` 包那个 shader 还轻。

**噪声是自写实现**，不引用 Inigo Quilez 的 CC BY-NC-SA 代码 —— 无授权问题。

### uniform 契约

⚠️ **索引由 GLSL 里的声明顺序决定**，两侧各写一份迟早会悄悄错位。
已抽成 `FluidBackgroundStyle.applyUniforms`，painter 与单测**共用同一份**。

| 索引 | uniform | 含义 |
|---|---|---|
| 0–1 | `uSize` | 画布宽高 |
| 2 | `uTime` | 着色器时间 = 真实秒数 × `style.speed` |
| 3 | `uSeed` | 本实例的图案偏移，见 §8 |
| 4 | `uWarp` | 扭曲强度 |
| 5 | `uGrain` | 颗粒强度 |
| 6–8 / 9–11 / 12–14 / 15–17 | `uColor1..4` | 四个颜色（RGB，0..1） |

## 6. 状态与生命周期

| 时机 | 行为 |
|---|---|
| `initState` | 无 `colors` 时发起取色；`useShader` 时发起着色器加载（**全局缓存**，多实例共用一次） |
| `didChangeDependencies` | 解析时钟来源（显式 > Scope > 自建），并按 `TickerMode` 起停自建时钟 |
| `didUpdateWidget` | `imageUrl` 变 → 重新取色；`colors` 变 → 直接换色；`clock` 变 → 重解析 |
| `dispose` | 释放 `FragmentShader` 与自建时钟（**Scope 的时钟由 Scope 自己释放**） |

**重绘机制**：`CustomPainter(repaint: clock)` —— 时钟每帧 notify，Flutter 只调 `paint()`，
**不 setState、不重建 widget 树**。外面套 `RepaintBoundary` 把重绘限制在本组件内。

## 7. 三条硬约束（都踩过坑，勿破坏）

### ① 噪声动画必须用单调递增时钟，不能用 `AnimationController.repeat()`

`repeat()` 的值域是 0→1 循环。**噪声不是周期函数，时间回绕会让画面瞬间跳变。**

> 同类坑在圆斑路径上也踩过，但圆斑可以靠「只用整数倍谐波」化解（数学是 2π 周期，
> 回绕点自然无缝）；**噪声不行** —— 所以必须换时钟，而不是改数学。

`FluidClock` 因此有两个非显然的设计：
- 值单调递增，永不回绕
- `stop()` 记住当前秒数、`start()` 从原处续上（Ticker 重启后 `elapsed` 会从 0 重算，
  不记住就会跳回 0）

有单测锁死这两点。

### ② 动画不得用 setState 驱动

每帧 `setState` = 每帧重建 widget 子树；再加 `CustomPaint(willChange: true)` 会关掉光栅
缓存。这正是 `mesh_gradient` 包（仍在 `pubspec.yaml`，但**代码零引用**）在本项目被换掉的
原因 —— **不是 shader 不好，是调用方式不好**。

正确写法：`AnimationController`/`ValueNotifier` 直接作 `CustomPainter` 的 `repaint`
Listenable。

### ③ 必须共享时钟 + 必须响应 TickerMode

- **共享时钟**：同屏多实例各起 Ticker 是浪费。用 `FluidBackgroundScope`。
- **响应 TickerMode**：`IndexedStack` 用 `Visibility(maintainAnimation: true)` 包未选中项，
  **TickerMode 不会被自动关掉**。所以 `main_screen.dart` 里给 `IndexedStack.children`
  逐项包了 `TickerMode(enabled: _currentIndex == i)`，Scope / 组件再按
  `TickerMode.valuesOf(context).enabled` 起停时钟。

> 有单测覆盖：「包了 Scope 两个实例只占 1 个 Ticker」/「没包 Scope 各起各的」/
> 「Scope 在 TickerMode 关闭时停帧」。

## 8. 让每一项有自己的流动动画（`seed`）

**只用时间相位错开是不够的。** 那样四张卡的**图案结构完全一样**（同条纹方向、同颗粒
结构），眼睛仍会读成「同一个图案」。

> ⚠️ **实测教训：像素差异大 ≠ 感知上不同。** 只错开时间相位时，相邻卡片的像素差异已有
> **66.6% / 80.8%**，但观感仍是一样的图案。**不要拿像素指标当感知判断的替代品。**

`seed` 必须同时作用在三处：

| 作用点 | 着色器里的写法 | 效果 |
|---|---|---|
| 旋转起始角 | `+ uSeed` | 条纹**方向**不同 |
| 噪声采样区域 | `+ vec2(uSeed * 37.0, uSeed * 91.0)` | **颗粒结构**不同 |
| 扭曲相位 | `+ uSeed * 3.0` | 色带起始位置不同 |

配合 `FluidBackground.seedForIndex(index) = index × π/4`，相邻项方向差 **45°**，
四张卡分别偏 0° / 45° / 90° / 135°。

实测：不同 seed 的图案差异 **92.4%**（且是结构性不同，不是相位平移）。

## 9. 可观测性

### ① 渲染路径埋点

着色器加载完成时记一条（全局一次）：

```
EventType.animActive
payload: { anim: 'fluidMeshShader', available: true|false }
```

调用方可另记自己的场景事件，例如首页的：

```
EventType.animActive
payload: { anim: 'mixCardFluidBackground', cards: 4, clock: 'monotonic' }
```

**为什么要这两条**：`frame.jank` / `frame.slow` 事件只带 `route`，同一页可能有多种背景
路径，无法归属。两条合起来即可判断本次运行的实际渲染路径，A/B 时不用靠记「我这次跑的
是哪个版本」。

### ② 取色埋点

`palette.extract`（含 `cacheHit` / `elapsedMs`）、`palette.evict`（缓存淘汰）。

## 10. 性能与红线

**每帧成本**（流沙路径）：
- Dart 侧：时钟 notify + `paint()` 里写 18 个 uniform + 一次 `drawRect`
- GPU 侧：约 9 hash/像素的逐像素计算
- **不重建 widget 树、不 setState**

**本项目红线（勿推翻）**：项目曾**特意移除**大面积毛玻璃（`glass_surface.dart:3`、
`mini_player.dart:93` 有代码考古证据）。所以：

- 本模块**不做 `BackdropFilter`**，不模糊背后的内容
- **不适合**铺在长列表的整页背景上
- 每期改动后需**低端安卓真机**验证滚动帧率（仅模拟器不算通过）

**帧率不过关时的第一个杠杆**：**降低着色器渲染分辨率**。软噪声场放大后观感几乎无损，
而 fill rate 可降约 4 倍 —— 做法是把 `CustomPaint` 放在一个固定小尺寸（如 72×72）的
`SizedBox` 里，外面用 `Transform.scale` 放大，并用 `ClipRect` 裁掉溢出。

## 11. 测试与验证方法

测试文件：`packages/fluid_mesh_background/example/test/fluid_background_test.dart`（17 例）。

**不要用「能编译」代替「画出来对不对」。** 本项目对 shader 做了三层验证：

1. **能编译** —— `flutter build bundle` 后检查 `build/flutter_assets/shaders/fluid_mesh.frag`
   是否存在（源码 2KB → 编译产物约 20KB），impellerc 报错即构建失败
2. **真的画出了会流动的场** —— **离屏渲染取像素**断言：
   - 全部像素不透明（背景不该有洞）
   - 空间上多色（不是一片纯色 → 噪声确实起作用）
   - 时间推进后大面积像素变化（确实在流，而不是静止）
3. **结构性差异** —— 不同 `seed` 的图案差异 > 40%

离屏渲染的写法（**可直接复用到别的 shader**）：

```dart
final shader = program.fragmentShader();
style.applyUniforms(shader, width: w, height: h,
    shaderTime: style.meshTimeFor(realSeconds), seed: seed, colors: colors);
final recorder = ui.PictureRecorder();
Canvas(recorder).drawRect(rect, Paint()..shader = shader);
final image = await recorder.endRecording().toImage(size, size);
final data = await image.toByteData(format: ui.ImageByteFormat.rawRgba);
```

环境不支持片段着色器时用 `markTestSkipped` 跳过（线上会回落圆斑，不影响功能）。

**已覆盖的回归点**：时钟单调性 / 圆斑 2π 周期性 / 跨回绕步长一致 / 流速倍率 < 1 /
不同 seed 图案差异 / seed 方向步进 45° / Scope 共享时钟 / TickerMode 停帧。

## 12. 已知限制与后续方向

| 限制 | 说明 |
|---|---|
| 长会话下 `uTime` 持续增大 | 着色器里噪声坐标会变大，float32 精度逐渐退化。按当前倍率，数小时量级仍可接受；若做常驻场景需要引入时间回绕（届时必须保证噪声坐标的连续性） |
| 图案仍是单频 | 自转/扭曲/噪声都基于同一个 `uTime`。理论上更「不重复」的做法是双周期叠加（如 x 走 16s、y 走 23s，合起来 368s 才重演），但当前观感已满足需求，未做 |
| 不含封面纹理 | 若将来要更接近 Apple Music 的「封面模糊」观感，需要把封面解码成 `ui.Image` 走 `sampler2D`。**注意**：本项目验证过「模糊封面缓慢平移」是**雾/云**观感，**不是沙**，两者不要混为一谈。若确实要重建该路径，参数配方见下 |
| 无「关闭动画」开关 | 目前无法在设置里关掉流动。若要做无障碍/省电开关，需在 Scope 层加 `enabled` 并停掉时钟 |

### 12.1 已回退方案「A：封面模糊纹理」的参数配方

2026-09-23 实现并验证过、随后**主动回退**（观感是雾/云不是沙，且解决不了「几个圆在动」）。
配方留档以便将来需要「雾/云」观感时直接重建，**不需要**新增 `ui.Image` 纹理管道：

```
AnimatedBuilder(                       // 每帧只重建这一层
  child: RepaintBoundary(              // ← 模糊结果缓存成图层，只栅格化一次
    child: ImageFiltered(ImageFilter.blur(sigma: 20),
      child: Transform.scale(2.6, child: Image(CachedNetworkImageProvider(...))))),
  builder: (…, child) => FractionalTranslation(平移) > Transform.scale(呼吸)
)
```

- 封面**先放大 2.6× 再模糊**：① 保留更多结构（直接糊 150px 会糊成一团）；
  ② 给平移留溢出量，不会露边
- 平移幅度 `0.035 / 0.025`（占卡片比例，**刻意比圆斑小**：纹理模式下「轻微动」才像背景）、
  缩放呼吸 `±0.06`
- 每帧成本 = 改一个矩阵 + 合成已缓存图层 ≈ 接近零
- 封面加载失败 → `errorBuilder` 回落取色圆斑，不留空白
- 该路径**不做取色**（省一次解码 + 调色板计算）

## 13. 移植到新模块的清单

1. `import 'package:fluid_mesh_background/fluid_mesh_background.dart';`（含 `FluidClock` / `FluidPalette` 的再导出）
2. 用 `FluidBackgroundScope` 包住需要共用时钟的区域（**单实例可省**：`FluidBackground` 自建时钟并按 `TickerMode` 起停）
3. 每个实例给 `FluidBackground(...)`，**网格场景务必传 `seed: FluidBackground.seedForIndex(i)`**
4. 若在 `IndexedStack` / `Offstage` / 自定义可见性切换里，**确认祖先有 `TickerMode`**
   （否则离屏仍在产帧）
5. 若实例数多或区域大，**上真机测滚动帧率**；不过关先降着色器渲染分辨率（§10）
6. 在其上压文字时显式 `showScrim: true` 并实测对比度；**压字位置分散（如上下都有字）时改用分区遮罩**，别让不压字的中段白挨一刀（见 §1「什么时候不该用」）
7. 需要场景埋点时按 §9-① 记一条 `EventType.animActive`

**不需要**改：`shaders/fluid_mesh.frag`、包内 `pubspec.yaml` 的 `flutter: shaders:`、`FluidPalette`。
