# Luobo 歌词页视觉对齐 Apple Music 技术方案

> 状态：方案已确认（2026-08-06 用户拍板"所有都按苹果的设计感来改"），已于 2026-08-06 实施
> 范围：全屏/桌面歌词页（`SyncedLyricsView`）+ 播放页内嵌精简歌词（`CompactLyricsView`）的视觉参数对齐 Apple Music 原生歌词页。**不动逐行滚动模型、不动架构、不加设置项**
> 设计约束：滚动/点击 seek/回当前行/逐字卡拉OK 等既有交互全部保留；仅调渲染常量（字号阶梯/透明度曲线/模糊/字重/行高/渐入/边缘淡出/去 glow）；纯渲染层改动，无数据/服务端改动
> 实施进度：✅ 已编码（2026-08-06）；新增单测全绿，`flutter analyze` 无新增 error，现有用例无破坏。真机/桌面视觉验证（§6）待进行

---

## 1. 背景与目标

### 1.1 用户反馈

1. 现在的逐行歌词滚动模型可以接受，不用改
2. 文字大小、已播/待播文字模糊度等 UI 细节与 Apple Music 不一致，希望按苹果设计感统一
3. 参考对象：Apple Music 原生歌词页 + amll-player 的类苹果呈现（后者非本方案重点，独立小窗已确认后置）

### 1.2 代码实证的结论

歌词页（`lib/widgets/synced_lyrics_view.dart`，1707 行）已经具备 AMLL 式滚动/高亮/模糊背景，但视觉参数与 Apple Music 原生歌词页存在 **8 处差异**，全部是渲染常量，集中在 3 条曲线函数 + `textStyle` + 若干常量，可小范围集中修改，不动渲染管线。

### 1.3 已确认决策（2026-08-06 用户拍板）

| 决策点 | 选择 |
|---|---|
| 模糊 | **去掉**（Apple 原生无模糊，远处行纯 alpha 淡出） |
| 透明度曲线 | **上下对称**：d1 0.5 / d2 0.28 / d3 0.16 / ≥4 0.08 |
| 字号阶梯 | **明显梯度**：1.0 / 0.88 / 0.80 / 0.74 |
| 字重 | 活动行 **w800**，其余 **w600**（首轮 w600/w400 实施后，2026-08-06 用户两次反馈"不够粗大"，逐档加粗至 w800/w600） |
| 字号 | 全屏 38 / 桌面 32 / 移动 30（首轮 32/26/24 基础上逐档 +2，用户反馈"不够大"） |
| 行高 | **1.4**（当前 1.35） |
| 行内渐入 | **0.5→1.0，前 10% 进度**（当前 0.28→1.0 前 15%，偏慢偏暗） |
| 边缘淡出 | stops 扩宽到 **0.18**（当前 0.10，太窄太硬） |
| glow | **全部去除**（当前活动/当前词带白色光晕，Apple 无） |

渲染管线相关事实（决定改动方式）：

- scale 走 `Transform.scale(alignment: centerLeft)`（`:1475-1478`）——**纯视觉缩放，布局行高不变**，滚动估算（`:1116`）不受字号阶梯影响
- opacity/blur/scale 都经 spring 动画插值（`_runSpring` `:1383-1407`）——曲线改动自动获得平滑过渡，无需额外动画工作
- blur 应用点有 `blur > 0.5` 守卫（`:1487`）——`_calculateBlur` 归零后该分支不再触发，blurAmount 管线保留供将来配置化
- 未来行是"内层文字 alpha × 外层 Opacity"**双重衰减**：内层 0.28（`:1652`）× 外层曲线（`targetOpacity`，`:1287` + `:1483-1485`），过去行只走外层曲线 → 这是现状"已播比待播亮"的机制根因
- `CompactLyricsView` 复用同一 `AMLLLyricsWidget`（`compact_lyrics_view.dart:246-249`，18px/lineGap 14/enableBlur false/align 0.5）——曲线改动自动生效，无需单独改

## 4. 具体改动点（全部在 `synced_lyrics_view.dart`，除 §4.9 新建文件）

### 4.1 去模糊

- `_calculateBlur`（`:1187-1195`）恒 `return 0.0`
- 更新文件头注释 `:1307`（"blur for distant lines" → 纯 alpha 淡出）
- 保留 blurAmount 管线与 `enableBlur` 参数不删，便于将来配置化；`blur > 0.5` 守卫使 ImageFiltered 不再执行

### 4.2 对称透明度曲线（含未来行内层修正）

`_calculateOpacity`（`:1206-1221`）改为上下对称：

```
d0 1.0 / d1 0.5 / d2 0.28 / d3 0.16 / ≥4 0.08（已播待播一致）
activeIndex < 0 兜底 0.55 保持
```

**关键配套修正**：未来行内层硬编码 alpha（`:1648-1653`）`0.28 → 1.0`。
原因：内层文字 alpha 与外层 `Opacity`（`:1483-1485`）相乘，现状未来行被双重衰减（0.28 × 曲线）。若只改外层曲线，未来行仍比过去行暗一个数量级，达不到对称。内层回 1.0 后，衰减统一由外层曲线承担，过去/未来行才真正对称。

### 4.3 字号阶梯

`_calculateScale`（`:1197-1204`）改为：

```
d0 1.0 / d1 0.88 / d2 0.80 / ≥3 0.74
activeIndex < 0 兜底 0.97 → 0.94
```

`Transform.scale` 为视觉缩放（`:1475-1478`），布局行高不变，无需改动滚动估算。

### 4.4 字重与行高（textStyle `:1502-1510`）

- `w800 → w800`（活动/选中）、`w700 → w600`（其余）—— 首轮按苹果 w600/w400 实施后，用户两次反馈"还是不够粗大"，于 2026-08-06 逐档加粗至 w800/w600；字号同步逐档 +2（全屏 38 / 桌面 32 / 移动 30，`:801`）
- `height 1.35 → 1.4`
- `letterSpacing -0.5` 保持

### 4.5 行内渐入加速（`:1603-1604`）

- fade 窗口 `0.15 → 0.10`
- 起步 alpha `0.28 → 0.5`（`alpha = 0.5 + 0.5 × fadeProgress`）

### 4.6 去 glow（4 处 shadows 全部移除）

- word 分支整行完成态（`:1533-1539`）
- word 分支当前词（`:1566-1575`）
- 行渐入中途态（`:1610-1621`）
- 活动/选中/已播态（`:1633-1644`）

word 分支内部 alpha 保持（已唱 0.85 / 当前 1.0 / 未唱 0.28，`:1548-1577`），与 Apple 逐字卡拉OK 观感一致，只去光晕。

### 4.7 边缘淡出加宽（ShaderMask stops `:1250-1256`）

`[0.0, 0.10, 0.90, 1.0] → [0.0, 0.18, 0.82, 1.0]`

### 4.8 无同步纯文本行对齐（`:1431-1451`）

`w700 → w400`、`height 1.35 → 1.4`（与正文一致；`isPlain` 分支仅在无同步歌词时整页显示）。

### 4.9 曲线可测化 + 单测（唯一结构性改动）

- 三条曲线函数（blur/scale/opacity）从 `_AMLLLyricsWidgetState` 私有方法提取为顶层函数，新文件 `lib/widgets/lyrics_visual_curve.dart`，签名：

```dart
double lyricBlur(int itemIndex, int activeIndex);
double lyricScale(int itemIndex, int activeIndex);
double lyricOpacity(int itemIndex, int activeIndex);
```

- 新增 `test/widgets/lyrics_visual_curve_test.dart`：断言各距离下 blur 恒 0、透明度上下对称（d1 0.5 / d2 0.28 / d3 0.16 / ≥4 0.08）、scale 阶梯（1.0 / 0.88 / 0.80 / 0.74）
- 目的：本方案改的是"视觉常量"，单测把这些数值钉死，防止后续调参回归；纯函数提取零风险

| 风险 | 应对 |
|---|---|
| 远处行 0.74 × 0.08 在移动端 24px 下过暗 | 真机观感不佳时回调 d≥3 scale 至 0.80 / ≥4 opacity 至 0.10（单点常量） |

| 对称曲线后"下一行"可读性下降 | 若预读需求强烈，可仅 d1 待播微调 0.55（与已播 0.5 轻微不对称），默认不做 |

**回滚：** 全部改动集中在 `synced_lyrics_view.dart`（常量）+ 1 个新曲线文件 + 1 个新测试，git 单 commit 可整体回退。

## 8. 双语歌词合并（2026-10-23 追加）

**问题**：双语 LRC 是「原文行 + 译文行」共用**同一时间戳**。播放时高亮**永远落在译文行**，且译文行一出现就是 100% 亮（进度按下一行时间算，同时间戳时 `end <= start` → 1.0）。

**方案（治本，用户拍板）**：**解析阶段合并**，不再按两行渲染。

- `LyricLine` 新增 `String? translation`；
- `SyncedLyrics` 构造函数统一归一化：**稳定排序**（时间戳相同按原下标）+ **同时间戳合并**（第一行为主行，其余文本进 `translation`，多行用 `\n` 连接）；
- ⚠️ **时间戳为 0 的行不合并**——纯文本歌词全是 0，否则整篇会被并成一行；
- 渲染：`_AMLLLineWidget` 主行 + 译文小字（`fontSize × 0.6`、白色 55%、行高 1.25），整行（含译文）跟随激活态缩放/淡入；`CompactLyricsView` 复用同一组件，自动生效；
- 高亮/滚动/点击 seek 全部以**合并后的行**为单位；车机链走独立 `LyricsManager`，不受影响。

单测：`test/models/lyrics_test.dart`（同时间戳合并 / 稳定排序 / 纯文本不合并 / 三行同戳）。

### 8.1 歌词行居中（2026-10-23 试版）

用户要求先看居中效果：`_AMLLLineWidget` 的 `TextAlign.left → center`、`Align/Transform.scale` 的对齐基准由 `centerLeft → center`，译文列 `CrossAxisAlignment.start → center`。触控范围仍是「只包文字」（Align 收缩到内容宽），多行歌词按行居中。全屏歌词页与 `CompactLyricsView` 共用该组件，同时生效。**若观感不佳，回退只需把三处 center 改回 left/centerLeft**。

### 8.2 行间距收紧 1/3（2026-10-23）

`lineGap` 在原值上收紧约 1/3：全屏 `24 → 16`、移动端 `14 → 9.5`；`CompactLyricsView` 同步 `14 → 9.5`。字号/行高（1.3）不变。

### 8.3 非当前行字号阶梯再收一档（2026-10-23）

原阶梯（相对当前行）：`1.0 / 0.88 / 0.80 / 0.74`；现改为 **`1.0 / 0.85 / 0.74 / 0.64`**（无活动行兜底 `0.94 → 0.90`）。以手机 26dp 计：当前行 26 → 相邻 22.1 → 隔一行 19.2 → 更远 16.6。实现是 `Transform.scale`，**不改变行高布局**，所以只影响观感、不影响滚动定位。已播/待播仍完全对称（仅 opacity 阶梯不同：0.5 / 0.28 / 0.16 / 0.08）。

### 8.4 车载歌词动效（2026-10-23）

车载页 `_CarModeLyrics` 原来是三行静态文本，且用 `StreamBuilder(positionStream)` —— 位置流 ≈5Hz，**每次 tick 都重建三个 Text**（行没变也重建）。

改成：

1. **StatefulWidget + 订阅位置流**，只有 `currentIndex` 变化时才 `setState`（平时静止，比原来更省）；
2. ~~过渡动画~~ **已移除（2026-10-23 用户拍板：换行效果不好）**——车载歌词保持静态替换，只保留「换行才重建」的性能优化；
3. 双语歌词的**译文小字**（**17** / 白 60%，初版 22 偏大已收）跟在当前行下面 —— 补回 `SyncedLyrics` 合并译文后车载侧丢失的信息；
4. 上一行/下一行保持静态（随整次重建一起更新）。

⚠️ 刻意**不做**：弹簧缩放、逐行字号阶梯、模糊/流体背景、逐字渐变 —— 车载是三行固定布局，且持续动画才是耗电大头。
