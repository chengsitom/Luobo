## 1. 背景与目标

### 1.1 用户诉求

用户认为飞牛音乐 App「审美非常好」，希望 Luobo 改成「和它一样的效果」，并强调——**核心不只是视觉，还有「一套整理好的交互逻辑」**。

### 1.2 对标物定位

飞牛音乐（fnos）是飞牛 NAS 的自研移动端音乐 App，**连自家服务端、可写回元数据**，因此其「歌曲信息」是完整可编辑表单。Luobo 是 Subsonic/OpenSubsonic 客户端（Navidrome / 道理鱼 / Jellyfin），**协议层不支持歌曲元数据写入**。

> **已拍板（2026-09-23）**：歌曲信息页**只展示、不修改**。原唯一硬卡点消除，「改歌手/改风格」选择器页**不做**。

### 1.3 目标

- **视觉**：把已有但零散的玻璃基建收敛为统一设计语言（token + 公共组件）
- **交互**：对齐 fnos 的页面骨架与各类浮层/列表/表单范式，补齐缺失页面
- **工程**：不推翻现有可用实现（悬浮底栏/播放条已达标），只做「收口 + 补页 + 统一浮层」

## 2. fnos 设计语言拆解

### 2.1 视觉配方

| # | 配方 | 取值（截图实测） |
|---|---|---|
| 1 | **悬浮** | 元素脱离屏幕边缘，四周留 12px 边距 |
| 2 | **大圆角** | 胶囊 `radius 30`；卡片 `16~20`；封面 `16~24`；按钮全圆 |
| 3 | **半透明白 + 模糊** | 白 `alpha 0.6~0.75` + `blur 12~24` + 1px 高光描边（白 `alpha 0.8`） |
| 4 | **柔和外阴影** | 黑 `alpha 0.12~0.18`、`blur 24~28`、`offset (0, 6)` |
| 5 | **强调色做实心色块** | 选中态是**玫红实心圆/胶囊**，不是图标变色 |

- 底色：浅色 = 浅灰 `#F2F2F7` 系；**深色 = 近黑 `#121212` 系**
- 卡片：浅色 = 纯白；**深色 = 深灰 `#1C1C1E ~ #2C2C2E`**
- 强调色：玫红，约 `#F0305C`（**深色下不变**）
- **渐变头图**：程序生成的大面积柔和渐变（绿 / 橙红黄 / 紫），中心一枚半透明图标（**深色下不变**）
- **深色模式已实测存在**（2026-09-23 补充截图），规范见 §2.9

### 2.2 页面骨架（3 种）

| 骨架 | 结构 | fnos 实例 |
|---|---|---|
| **大标题页** | 左对齐大字标题 + 右上悬浮圆钮 | 首页、音乐库、设置 |
| **列表页** | **居中标题** + 左上圆返回 + 右上圆（搜索 / `···`）；下方「共 N 首」+ 视图/排序图标 | 全部歌曲、专辑、歌手、音乐风格、最近播放、收藏 |
| **模态表单页** | 左上圆（`×` 或 `←`）+ 居中标题 + 右上**实心圆 ✓** | 新建歌单、歌曲信息、修改歌手、修改风格 |
| **全屏播放页** | 无 AppBar；**整屏封面模糊放大为背景** + 左上 `⌄` 下箭头收起；全白文字 | 正在播放 |
| **折叠头详情页** | 头图随滚动收起；**分段控件（歌曲｜专辑）从内容区「迁移」到顶栏右侧**，同时返回圆钮变成**带标题的胶囊** | 歌手详情页 |

> **列表页头部再分两型**：
> - **普通头**：标题 + 「共 N 首」+ 视图/排序图标（全部歌曲、专辑、歌手、音乐风格）
> - **头图式**：超大渐变封面 + 居中标题 + **双黑胶囊按钮**（`▶ 播放` / `⤨ 随机`）（最近播放、收藏、歌单详情）

### 2.3 列表与卡片范式（4 种呈现）

| # | 呈现 | 特征 | fnos 实例 |

| 1 | **分组白卡** | 一张白卡装一组同类项，组内分隔线**缩进到文字起始处** | 设置页、音乐库页 |

> ⚠️ **右侧位必须贴右边缘（2026-09-23 用户指出，我首版设计稿写错）**
> - **chevron 永远贴右边缘**，**不紧跟文字** —— 无论该行有没有状态值

> - 无状态值时：`文字 … ›`（chevron 自己撑到最右）
> - 实现要点：chevron 用 `margin-left: auto`（Flutter 里即 `Spacer()` 或 `Expanded` 包裹文字），**有状态值时再让状态值接管 `auto`、chevron 改回固定间距**
>
> 首版 HTML 稿把 chevron 写成固定 `margin-left: 7px`，导致无状态值的行 chevron 紧跟文字 —— 已修正。**这条在 C1 的 `SettingsTile` 组件里要一次做对，否则会污染所有行。**

### 2.5 表单范式

- **可编辑字段**：**标签在卡片外**（小字），输入框是独立白卡
- **只读信息**：`label + value` 竖排**排在卡内**（文件位置 / 文件大小 / 添加日期）
- 二者用不同呈现，一眼区分可否编辑
- **灰字说明**：单选/开关项**下方跟灰字解释**；小节标题也在卡外
- **已选 chip**：玫红淡底胶囊 + `×`（搜索框下方流式排列）
- **封面预览**：大方形封面 + 两个**圆形悬浮小按钮**（`↻` 换一张 / `✏️` 编辑）+ 灰字格式说明（「支持JPG、JPEG、PNG、WEBP，大小<5MB」）

### 2.8 交互设计原则（「交互也很好」的底层原因）

> 用户明确强调「不只是审美，交互也很好」。**视觉是表层，以下原则才是这套设计的价值所在**——实现时只抄视觉而丢掉这些，会得到「像 fnos 但更难用」的结果。

**核心命题：用「空间位置」表达作用域，而不是用文字标签。**

| # | 原则 | 具体表现 | 反例（要避免的） |
|---|---|---|---|
| 1 | **操作密度恒定** | 任何页面的全局可点元素固定为：左上 1 + 右上 1 + 底部 1。页面再复杂，「在哪点」都不变 | 每个页面按钮位置/数量都不一样，用户需重新找 |
| 2 | **位置编码作用域** | 左上=离开本页；右上=对本页的动作（搜索/更多/保存）；底部=跨页面（导航/当前播放）；行右=对这一个对象 | 把全局操作和行内操作混在同一区域 |
| 3 | **状态外显，不靠进入** | 行右侧直显状态值（`1009.48 MB` / `V1.0.1` / `460 首歌`）；排序菜单直显当前选中项 + 方向；已选 chip 直显已选项 | 要「点进去看一眼再退出来」才知道当前状态 |
| 4 | **决策降维** | 排序 = **字段 × 方向**两个维度：菜单列字段，勾选 + 箭头表达方向，再点同项切方向 | 把方向烤进标签、平铺成 N 个选项（见 §3.2 #23） |
| 5 | **危险靠视觉重量劝退，不靠弹窗打断** | 淡红底 + 红字 + 单独一行 + 置于末尾 | 一律弹 AlertDialog 二次确认，打断流程 |
| 6 | **模式切换显式化** | 多选 = 从底部升起全新全屏 sheet，且**底部操作栏先告知「选完能干什么」** | 在原列表上叠勾选框，模式边界模糊 |
| 7 | **唯一退出路径** | 进任何一层，都从同一个位置（左上）退出 | 有的页面可滑退、有的要按钮、有的要返回键 |
| 8 | **内容与操作空间分离** | 列表行只负责「选择」，行内不放操作按钮（仅最右 `⋮`），保证列表可扫读 | 行内塞满图标按钮，破坏扫读 |
| 9 | **浮层锚定而非居中** | 排序菜单从触发按钮旁展开，视线不需重新定位 | 弹到屏幕中央，来源与结果位置分离 |
| 10 | **一致性到肌肉记忆** | 「左上圆返回」出现在每张二级页；「右上实心圆 ✓」出现在每处保存 | 同类操作在不同页面形态不同 |

**一句话**：你不需要读任何标签，**看位置就知道这个操作作用在什么范围**。

### 2.9 深色模式规范（2026-09-23 实测补充）

深色模式**已实测存在**（首页 / 歌手页 / 设置页 / 排序浮层 / 歌曲 `⋮` 面板 共 5 张深色截图）。核心结论：

| 元素 | 浅色 | 深色 | 变化 |
|---|---|---|---|
| 页面底色 | `#F2F2F7` | **近黑 `#121212` 系** | 换色 |
| 内容卡片 | 纯白 | **深灰 `#1C1C1E ~ #2C2C2E`** | 换色 |
| 卡片文字 | 黑 | 白 | 换色 |
| 副标题文字 | 灰 `#8E8E93` | 灰（略亮） | 换色 |
| 分隔线 | 浅灰 | 深灰细线 | 换色 |
| **强调色（玫红）** | `#F0305C` | **不变** | ✅ 不换 |
| **图标（玫红线性）** | 玫红 | **不变** | ✅ 不换 |
| **悬浮玻璃** | 白 `alpha 0.6~0.75` + 模糊 | **黑 `alpha ~0.5` + 模糊 + 白 `alpha 0.1` 描边** | 换 tint，保留模糊 |
| **渐变头图 / 渐变卡** | 绿 / 橙红黄 / 紫 | **完全不变** | ✅ 不换 |
| **结构 / 圆角 / 间距 / 字阶** | — | **完全一致** | ✅ 不变 |

**关键推论**：深色模式**只换颜色 token，不换任何结构**。这意味着 §4.1 的 `design_tokens.dart` 必须**从一开始就双色定义**（`LuoboColors.light` / `.dark`），否则后期补深色会返工。

**⚠️ 深色玻璃圆钮的可见性陷阱（2026-09-23 设计稿暴露）**

深色下玻璃 tint 是 **黑 `.50`**，本身几乎不可见。它的可见性来自三件事：

1. **`backdrop-filter` 模糊**——底下必须有内容可模糊
2. **白 `.10` 描边**
3. **阴影**

**因此深色玻璃圆钮不能放在纯色深色平面上**（纯黑底 + 黑 tint = 消失）。设计稿首版把深色态示例放在 `#121212` 平面上，整个按钮看不见 —— 已修正为浮在暗色渐变上。

**实现约束**：C1 的 `GlassCircleButton` 在深色下必须保证「底下有内容」；若某页面确实是纯色深底（如全屏播放页的纯色态），需**加强描边**或改用淡底变体。

**一处待确认**：深色设置页截图里，大标题「设置」被账号卡片**部分覆盖**，无法判断大标题是「固定 AppBar」还是「随内容滚动的页内标题」。浅色截图（未滚动）看不出差别 → 列入 §7 待确认。

### 2.10 全屏播放页规范

**布局（自上而下）**

1. **背景**：**彩色渐变流体动态背景**——从当前封面**取色**，整幅被噪声场平流、**持续流动**（Apple Music 式「流沙」），上覆线性暗渐变保证白字可读。设计语言见 §2.11，实现见 `docs/流沙流体背景技术文档.md`
2. **左上**：`⌄` 下箭头（收起播放页，非返回）
3. **封面**：居中大图
4. **信息行**：左 = 歌名（大）+ 歌手（灰）；右 = `♡` 收藏 + `⋮` 更多
5. **进度条**：细线 + 圆点手柄
6. **时间行**：左 = 已播时长；**中 = 转码状态 · 格式 · 码率**（如 `转码 · OPUS · 192 kbps`）；右 = 总时长
7. **控制行（5 按钮）**：`⟳` 循环 / `⏮` 上一首 / `▶⏸` 播放暂停（最大）/ `⏭` 下一首 / `☰` 队列
8. 全白文字（因背景是封面）；**无底栏、无播放条**

### 2.12 折叠头：分段控件迁入顶栏

**用户 2026-09-23 特别指出这个交互**（歌手详情页）。以歌手详情页为例：

| 滚动状态 | 顶栏 | 分段控件位置 |
|---|---|---|
| **未上滑** | 左上**独立圆返回** | 在**内容区**：歌手名 + 统计下方，与 `▶ 播放全部` 黑胶囊同一行 |
| **上滑后** | 返回圆钮变成 **`← 歌手名` 胶囊** | **迁入顶栏右侧**，与返回胶囊同一行；`▶ 播放全部` 消失 |

**本质**：**同一个分段控件，随滚动「迁移」到顶栏**（横向位置也变了，不只是纵向跟随）。

**实现要点**：单一 widget 无法跨 parent 平滑移动，标准做法是**两处渲染 + 按滚动进度交叉过渡**（或带位移的动画），由同一个 `ScrollController` 驱动；顶栏侧用 `SliverAppBar` / `SliverPersistentHeader` 的 pinned 态承载。

**Luobo 现状差异**：`artist_screen.dart:264` 用 `SliverAppBar(pinned, expandedHeight: 200)` + `FlexibleSpaceBar`，内容是**纵向堆叠**（热门歌曲区块 + 专辑区块），**没有分段控件**，也没有折叠迁移。→ 属**页面级重构**（见 §3.2 #24）。

### 2.11 彩色渐变流体动态背景

> **已拍板理解（2026-09-23 用户指出）**：fnos 里「很多渐变图」用的不是静态图，而是**彩色渐变流体动态背景**——即 Apple Music 那套「**专辑封面色彩提取 + 不断流动**」的背景。

**设计语言要点**（仅记与本方案相关的部分）

- **取色**：从封面提取调色板（vibrant 优先，回落 dominant）
- **连续场**：不是「几个圆在动」，而是整幅被噪声场平流的**连续场**（用户原话「像流沙似的」）
- **持续流动**：静止时也在缓慢流动，**不是**只在换封面时过渡
- **可读性遮罩**：上覆线性暗渐变，保证白字可读
- **降级**：取色失败 / 无封面 → 回落默认深色 mesh

**应用面**（本方案涉及）：全屏播放页背景、头图式列表页头图（收藏 / 最近播放 / 歌单）、首页渐变卡。

> 📄 **实现细节不在此文档**：技术方案、公共 API、着色器原理、三条硬约束、调参旋钮、测试方法、移植清单，见独立文档 **`docs/流沙流体背景技术文档.md`**；首页落地背景见 `docs/首页重构技术方案.md` §5.6-§5.8。**本方案只消费该模块，不复述其实现。**
>
> ⚠️ **早先更正留档**：本方案曾把 Luobo 播放页背景描述为「渐变 blob，不如 fnos 的封面放大模糊」——**这是错的**。Luobo 的实现与 fnos 同源（Apple Music 式取色流体），且已抽为公共模块。

## 5. 性能约束与红线

**红线：不做「处处毛玻璃」。**

项目**曾特意移除大面积毛玻璃**，两处代码考古证据：

| 证据 | 内容 |
|---|---|
| `lib/widgets/glass_surface.dart:3-5` | 注释明说旧毛玻璃包装被换成实色：*"BackdropFilter-free solid bottom sheet. Kept as a drop-in replacement for the previous frosted-glass wrapper"* |
| `lib/widgets/mini_player.dart:93-95` | 注释明说 sigma 从 24 降到 12 是为省 GPU：*"Lower sigma keeps the glass look while costing far less GPU per frame"* |

**执行原则**

- `BackdropFilter` **只用于小面积固定元素**：底栏、播放条、悬浮圆钮、锚定菜单
- **禁止**用于：列表项、滚动中的大面积卡片、整页背景
- 所有玻璃元素必须包 `RepaintBoundary`（`mini_player.dart:77` 已有先例）
- **播放条改覆盖式后**（§4.2-④）模糊面积不变，但滚动内容会从其下方经过 → **必须实测**帧率
- 每期改造后需**低端安卓真机**验证滚动帧率（仅模拟器验证不算通过）
