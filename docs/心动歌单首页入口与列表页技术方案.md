# 心动歌单接入技术方案（首页入口 + 列表页）

> 2026-10-27 · 状态：**已实施（待真机验收）**
>
> 本期目标：道理鱼登录时，在首页第一排新增「心动歌单」入口；点进去是列表页，先验证好不好用。**飞牛音乐不展示**。AI 歌单页本期不动。

## 1. 目标与范围

- **入口**：首页第一排（`HomeV2Screen` 的 `_heroRow`）新增第 4 张卡「心动歌单」，仅在道理鱼服务器下构建。
- **列表页**：展示服务端生成的 12 组歌单，支持「换一批」、进入详情、播放、保存。
- **详情页**：曲目列表 + 播放全部 / 随机播放 + 右上角保存歌单（二次确认、防重复）。
- **不做**：AI 歌单页改造、首页独立推荐区、服务端播放队列、歌单筛选（风格/场景）。
- **不依赖 DeepSeek API Key**。

## 2. 接口实测（2026-10-27，登录态抓取）

### 2.1 列表

```http
GET /api/library/heart-playlists?count=12
Authorization: Bearer <JWT>
```

```json
{
  "batchId": "batch_349861bd3960f3bd",
  "generatedAt": "2026-10-27T09:00:18Z",
  "genres": [],
  "scenes": [],
  "availableGenres": ["pop", "rock", "民谣", "流行", "独立"],
  "availableScenes": ["孤独", "思念", "放松", "旅行", "治愈", "浪漫", "酒吧"],
  "playlists": [
    {
      "id": "batch_349861bd3960f3bd_b6589fc6ab0dc82c",
      "name": "流行、华语里的下班后的慢慢走 · 第89辑",
      "description": "想进入“驾车、放松”的状态……",
      "genres": ["流行", "华语"],
      "scenes": ["驾车", "放松"],
      "trackCount": 60,
      "totalDurationSeconds": 15400.82,
      "coverUrls": ["/api/cover?path=%2F...", "..."]
    }
  ]
}
```

- `count` 不是「从当前批里返回几条」，而是**选择某一批预生成歌单的规模**：实测 `count=1/3/5` 都返回 6 组，`count=8` 返回 8 组，`count=12` 返回 12 组。注意 8 与 12 是**不同批次**（名称、辑号都不同），不是「8 组 + 4 组」。
- 道理鱼 Web 的 `/heart-playlists` 页面请求的是 `count=8`；Luobo 按用户 2026-10-27 要求改为 **`count=12`**，以展示完整 12 组。
- 不传 `refresh` 时同一 `count` 稳定返回同一批，不会每次打开都重新生成。
- 「换一批」传 `refresh=<毫秒时间戳>-<随机串>`，返回新批次。
- **手机端右上角刷新按钮 = Web「换一批」**：两者都是带 `refresh` 请求同一个列表接口，效果一致（服务端换一批新歌单）；区别只是 Web 还有风格/场景筛选，Luobo 本期不做筛选。

### 2.2 详情（含曲目）

```http
GET /api/library/heart-playlists/{playlistId}
Authorization: Bearer <JWT>
```

响应在列表字段之外增加：

- `trackIds: string[]`：完整曲目 ID 列表；
- `tracks: Track[]`：完整曲目对象，字段与 `/api/library` 曲目一致。

注意：

- `/api/playlists/{id}` 对心动歌单返回 **404**，不能复用普通歌单详情；
- `/api/library/heart-playlists/{id}/tracks` 返回 **501**，曲目只能从详情响应的 `tracks` / `trackIds` 取；
- 详情一次返回全部曲目（最多 100 首），点开卡片时再请求。

### 2.3 封面

`coverUrls` 是不带票据的 `/api/cover?path=...`，直接加载会 401/403。需要票据时：

```http
POST /api/library/cover-tickets
Authorization: Bearer <JWT>
Content-Type: application/json

{"items":[{"path":"/app/runtime/data/scanner-covers/xxx.jpg","size":100}]}
```

响应 `items[]` 取 `url`（已带 ticket），票据约 120 秒有效。

> **单次最多 32 个 item（2026-10-27 实测）**：`items.length=32` → 200；`33/34/36/40/47` → **400 `INVALID_INPUT`**。12 组 × 4 张 = 48，**不能一次提交**；Luobo 按 12 个一批分 4 次申请，第一批只覆盖前 3 行，首屏更快。
>
> 实测耗时（远程 ugdocker 反代）：列表接口约 **1.6s**；12 个票据约 **150ms**；12 张封面图最快 **174ms** / 中位 **820ms** / 最慢 **1.3s**。所以「慢」主要来自列表接口本身 + 48 张图逐张下载，而不是票据。

## 3. 首页第一排入口

### 3.1 位置与顺序

现有第一排（`home_v2_screen.dart` `_buildHeroEntries`）：漫游 → 收藏 → 最近播放。

新增后：**漫游 → 收藏 → 心动歌单 → 最近播放**。

- 用户 2026-10-27 拍板：心动歌单放第 3 位，最近播放顺延到第 4 位。
- 仍是横滑行，不铺满；新增后共 4 张，右侧自然露出下一张。

### 3.2 卡片样式

复用 `HomeHeroCard`，与现有三张保持同一尺寸（151×184）：

- 图标：`Icons.auto_awesome`（或心形 + 音符组合图标）。
- 标题：`心动歌单`。
- 副标题：`12 组 · 每日更新`；如果列表已加载，可显示 `第 738 辑`。
- 配色：暖玫红 → 橙的流体渐变，和「漫游（蓝紫）/ 收藏（玫红）/ 最近播放（抹茶绿）」区分开。
- 点击：`NavigationHelper.push(context, const HeartPlaylistsScreen())`。

### 3.3 平台门控（飞牛不展示）

硬约束，必须用**白名单**，不能用「非飞牛就显示」：

```dart
bool get _showHeartPlaylists {
  final config = context.watch<AuthProvider>().config;
  if (config == null) return false; // 未登录 / 配置未加载
  final family = config.serverFamily.toLowerCase();
  final type = (config.serverType ?? '').toLowerCase();
  return family == 'daoliyu' || type.contains('daoliyu');
}
```

- **道理鱼**：显式 `serverFamily == 'daoliyu'`，或自动检测配置的 `serverType` 含 `daoliyu` → 显示；
- **飞牛音乐**：走 Subsonic/OpenSubsonic 兼容层，`serverFamily` 是 `subsonic` / `auto`，`serverType` 不含 `daoliyu` → **整张卡不构建**；
- **其它服务器 / 本地曲库 / 未登录**：同样不构建；
- 用 `context.watch<AuthProvider>()`，切换服务器后入口立刻消失。

## 4. 列表页设计

页面：`HeartPlaylistsScreen`，路由从首页卡片 push。

### 4.1 视觉骨架

```
┌────────────────────────────────────────┐
│  (← 心动歌单)                    (↻)   │  ← 透明顶栏：返回+标题 40dp 胶囊 / 右侧圆钮
│                                        │
│  今日心动                               │  ← 小标签 11/600，玫瑰色
│  为你组合的 12 组歌单                    │  ← 大标题 24/800
│  根据你的曲库风格与场景，每天换一批         │  ← 副标题 13，次要色
│  第 738 辑 · 更新于 10:00                │  ← 元信息 11，三级色
│                                        │
│  ┌──────┬───────────────────────────┐  │
│  │ ▦▦   │ 流行、华语里的下班后的慢慢走  │  │  ← 2×2 拼图 84dp + 标题 2 行
│  │ ▦▦   │ 想进入“驾车、放松”的状态…    │  │     描述 1 行
│  │      │ 流行 华语 驾车 放松          │  │     标签胶囊
│  │      │ 60 首 · 4 小时 16 分      ›  │  │     元信息 + chevron
│  └──────┴───────────────────────────┘  │
│  ┌──────┬───────────────────────────┐  │
│  │ ▦▦   │ 夜色慢慢降临 …              │  │
│  └──────┴───────────────────────────┘  │
│  … 共 12 条                            │
└────────────────────────────────────────┘
```

### 4.2 顶栏

按现有二级页规范（`feedback_page_header_pill`）：

- 透明顶栏，无实色底、无居中标题；
- **左侧初始只有 40dp 返回圆钮，不带标题**；上滑超过 **64dp**（隐藏阈值 56dp，8dp 回滞防闪烁）后，才切换成「返回 + 心动歌单」40dp 胶囊；
- 右侧一个 40dp 玻璃圆钮，图标 `Icons.refresh_rounded`，tooltip「换一批」；
- 加载中：顶栏下方显示 2dp 进度条；换一批请求进行中忽略重复点击；失败：Toast，保留旧列表。

### 4.3 页头信息块

- 左对齐，左右 20dp。
- `今日心动`：11/600，字距 1，强调色（玫瑰）。
- `为你组合的 12 组歌单`：24/800，行高 1.2。
- 说明：13/400，次要色。
- 元信息：11/400，三级色；`第 N 辑` 从列表第一项名称末尾提取，`更新于` 用 `generatedAt` 本地时区。
- 不加通栏渐变 hero：首页入口卡已经有视觉重量，列表页再加一块会重复；页头用文字层级撑起来更轻、更像「列表页」。

### 4.4 列表行

每行是一张白/深色卡（浅色 `Colors.white`，深色 `#1C1C1E`），圆角 18，内边距 12，行间 12：

- **左侧 2×2 拼图**：84×84，圆角 12，2dp 间隙；4 张封面来自 `coverUrls`（票据 URL）；不足 4 张时重复第一张或用渐变占位。
- **右侧**：
  - 标题：15/600，最多 2 行；长名称按 `·` 智能断行（沿用 `home_hero_card.dart` 的 `_HeroTitleText` 思路）。
  - 描述：12/400，次要色，最多 1 行，省略。
  - 标签：最多 4 个胶囊（`genres` + `scenes`），10.5/500，强调色 10% 底 + 强调色文字；超出省略。
  - 元信息：11/400，三级色，`60 首 · 4 小时 16 分`。
  - 尾部：`Icons.chevron_right_rounded` 18，三级色；整行可点。
- **按压反馈**：`InkWell` + 轻微缩放（0.98），不弹新页动画。
- **不做播放按钮**：列表页的主动作是「选一组进去听」，行内再放播放按钮会让「点行」和「点播放」两个目标打架；播放全部放到详情页。

**加载策略（2026-10-27 实测后调整）**

- **列表先渲染**：`getHeartPlaylists` 一返回就 `setState` 出列表，封面先占位；不要等票据全部到齐。
- **票据分批**：接口单次上限 32，按 **12 个一批**（前 3 行）申请，后续批次在后台补；每批回来立刻 `setState` 合并。
- **按需建行**：用 `ListView.builder`，只构建可视区附近的行；旧实现 `ListView(children:)` 一次建 12 行，会同时发 48 张封面请求。
- **稳定缓存键**：`heart-cover-<serverId>-<path>-<size>`，不含 `ticket` 与 host；LAN↔公网切换、重复进页面都不会重下同一张图。

### 4.5 加载 / 空态 / 失败

- **加载**：6 条骨架行（84dp 灰块 + 三行灰条），不用全屏转圈。
- **空态**：`EmptyState` 心形图标 + 「还没有心动歌单」+ 「去道理鱼 Web 首页打开一次心动歌单，或先补齐歌曲的风格/场景标签」+「重试」。
- **失败**：同上，文案改为「加载失败」+「重试」。
- **下拉刷新**：`RefreshIndicator`，与顶栏「换一批」走同一个请求。

### 4.6 为什么用「纵向列表 + 2×2 拼图」

- 心动歌单名称很长（20+ 字），2 列网格会大量截断；列表行能放 2 行标题 + 1 行描述。
- 2×2 拼图是 Web 上心动歌单的识别符号，保留它能让用户一眼认出来。
- 12 条大约两屏，列表比网格更适合「扫一眼选一组」。
- 不推荐 2 列网格：卡片宽度约 160dp，标题只能显示 8～10 个字，12 组歌单会长得一模一样。

## 5. 详情页设计

页面：`HeartPlaylistDetailScreen`。

- 顶栏：**初始只有返回圆钮，不带标题**；上滑超过 **160dp**（大约把 168dp 拼图滑出视口；隐藏阈值 152dp，8dp 回滞）后，才切换成「返回 + 歌单名」40dp 胶囊。右侧常驻「保存」圆钮（未保存 `playlist_add` / 已保存 `playlist_add_check`）。
- 底部净空：统一用 **`LuoboSpacing.pageBottomWithStrip(context)`**（= 32 + `MediaQuery.padding.bottom`；`MainScreen` 的 `extendBody` 会把播放条高度注入 body 的 MediaQuery），**不要写死 100/40**。列表页、骨架、空态同样用这个值。
- 头部：
  - 2×2 拼图 160×160，居中或左对齐；
  - 歌单名 22/800，最多 3 行；
  - 描述 13/400，最多 3 行；
  - 标签胶囊 + `60 首 · 4 小时 16 分`；
- 主操作：
  - `播放全部`：强调色实心胶囊，主按钮；
  - `随机播放`：白底/玻璃次按钮（原「保存歌单」胶囊的位置）。
- 保存：右上角圆钮（未保存 `playlist_add` / 已保存 `playlist_add_check`），点击后走 `showLuoboConfirmSheet` 二次确认；保存前按歌单名查 `LibraryProvider.playlists`，已存在则 Toast「这个歌单已经保存过了」，不重复创建。
- 曲目列表：复用 `SongTile`，显示序号；**禁用左滑移除**（服务端歌单，本地移除会误导）。
- 返回：保留列表页状态，不重新请求。

## 6. 数据层

### 6.1 新模型 `lib/models/heart_playlist.dart`

```dart
class HeartPlaylist {
  final String id;
  final String name;
  final String description;
  final List<String> genres;
  final List<String> scenes;
  final int trackCount;
  final double totalDurationSeconds;
  final List<String> coverUrls;
  final List<String> trackIds;
  final List<Song> tracks; // 列表接口为空，详情接口填充
}
```

纯函数：

- `HeartPlaylist.fromListJson(...)`
- `HeartPlaylist.fromDetailJson(...)`（`tracks` 复用公开的 `songFromDaoliyuTrack`）

### 6.2 `SubsonicService` 新增方法

```dart
Future<List<HeartPlaylist>> getHeartPlaylists({int count = 8, String? refresh});
Future<HeartPlaylist?> getHeartPlaylistDetail(String playlistId);
Future<Map<String, String>> fetchDaoliyuCoverTickets(List<String> paths);
```

- 全部走 `_apiGet` / `_apiPost`（已有 JWT 登录与 401 重登）；
- 非 `isDaoliyu` 返回空 / null；
- 把私有 `_daoliyuTrackToSong` 暴露为公开 `songFromDaoliyuTrack`，详情解析与随机歌共用；
- 票据缓存：`path → (url, expiresAt)`，提前 15 秒过期；批量申请。

### 6.3 缓存

- 列表：页面 State 内存缓存；「换一批」替换。
- 详情：按 `playlistId` 缓存在页面 State；换一批后旧 id 自然失效。
- 不落盘：`batchId` 与有效期由服务端决定。

## 8. 测试与验收

**单测**

- 列表解析：12 条、缺字段、空 `playlists`；
- 详情解析：`trackIds` 与 `tracks` 数量一致、坏 track 跳过；
- 非道理鱼：服务层返回空；
- 门控：`daoliyu` 显示，`subsonic` / `auto`（飞牛）不显示。

**真机**

1. 道理鱼登录 → 首页第一排出现「心动歌单」；
2. 点进去 → 12 条卡片、封面拼图正常；
3. 换一批 → 名称/批次变化，旧列表不闪空；
4. 点一条 → 详情曲目、播放全部 / 随机播放、右上角保存（二次确认、重复保存被拦截）；
5. 退出重进 → 列表仍在（同一批次）；
6. 切飞牛登录 → 首页没有这张卡，直接访问页面也不请求接口。

## 9. 风险与决策点

1. **封面拼图**：一期就做，因为它是列表页的主要视觉；票据 120 秒过期，需做提前刷新。若实现成本超预期，退回「渐变占位 + 首张封面」。
2. **名称过长**：标题 2 行 + 描述 1 行；详情页给 3 行。不要为了塞全名缩小字号。
3. **保存语义**：保存后是普通用户歌单，不与心动歌单同步；按**歌单名**判重，同名已存在时不再创建。
4. **左滑移除**：详情页禁用。
5. **空列表**：服务端标签缺失时可能没有歌单；空态文案指向「补齐风格/场景标签」。
6. **平台范围**：只在道理鱼显示；飞牛及其它服务器整卡不构建，白名单判断见 §3.3。
7. **首页并行改动**：`home_v2_screen.dart` / `home_hero_card.dart` 近期有其他改动，接线时要先确认工作区状态，避免覆盖。

1. 模型 + 解析纯函数 + 单测。
2. `SubsonicService` 三个方法 + 单测。
3. 列表行 + 列表页 + 骨架/空态。
4. 详情页 + 播放/保存。
5. 首页第 4 张卡 + 门控。
6. 真机验收。
